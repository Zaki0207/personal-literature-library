# 我的文献库

一个面向个人研究流程的文献管理前端原型，当前版本聚焦于：

- 精简的搜索、筛选、排序与添加入口
- 最多三级、层级可选的论文分类
- 可控制一级分类是否显示在侧栏
- 带论文数量的当前分类总览与下级分类快速导航
- 中英文标题、作者机构、AI 总结与个人笔记
- 固定展示 PDF、代码和项目主页的资源状态
- 可与分类组合的收藏、近期想看筛选和移动端导航
- 可添加多个 AI 服务连接，在同一 Base URL 下配置并切换多个模型

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

打开终端输出的本地地址即可查看。

## 验证

```bash
npm run build
node --test tests/rendered-html.test.mjs
```

文献数据保存在本机 SQLite 数据库中；每次有效修改后会在 iCloud
Drive 中生成经过完整性校验的版本备份。

浏览器构建不包含任何个人文献、笔记或 Zotero 导出内容。一次性 Zotero
导入数据默认写入被 Git 忽略的 `local-data/library-data.json`，仅在本机
数据库为空时用于初始化；文件不存在时会安全地启动为空文献库。

## AI 服务配置

启动本地应用后，点击顶部的“AI 设置”，添加由服务名称、Base URL 和
API Key 组成的服务连接，再为连接填写模型 ID。同一连接下的模型共享密钥；
每个模型经最小请求验证成功后才会保存，并可独立设为当前模型。

API Key 只保存在 macOS 钥匙串中，不写入浏览器存储、SQLite、iCloud
备份、环境变量或日志。SQLite 只保存服务名称、Base URL、模型 ID、验证
时间和当前模型状态。Base URL 只允许 HTTPS 或本机 HTTP 地址，不能包含
用户名、密码、查询参数或片段；更改地址时必须重新输入 API Key，以确认
新的发送目标。AI 请求会自动沿用应用启动时可用的 HTTP/HTTPS 网络代理；
代理设置中不包含 AI 密钥。服务连接优先使用 Responses API；如果
兼容服务明确返回接口不存在（404），会自动改用 Chat Completions API。
